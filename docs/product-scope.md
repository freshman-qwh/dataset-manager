# 产品定位与功能取舍

更新日期：2026-11-06。本文约束当前产品入口和后续需求取舍；实际功能以源码为准，任务状态以 [TODO](../TODO.md) 为准，操作步骤见 [快速验证指南](quick-validation-guide.md)。旧方案用于说明决策背景，不覆盖当前边界。

## 产品服务谁、交付什么

Dataset Manager 是面向工业视觉研究与小规模验证的**本地工业数据准备与快速验证工具**。主要使用者需要把一批相机图片整理为可信的正常/异常样本，确认工件隔离，在独立数据上检查基线表现，并能复用到下一批图片。

一次工作应交付以下一项或多项结果：

- 可追溯的图片判定、工件组和采集批次。
- 纯正常训练、独立验证/测试的数据包，包含真实图片副本及读取说明。
- 可回看输入和人工真值的 CPU 基线实验、误报漏检候选及结果报告。

通用分类、检测和分割属于已有兼容能力。工业图像级判定不要求普通样本标签、画框、几何标注审核或 SAM。原图始终留在原目录；导出显式复制，整理与验证不改写原图。

当前快速验证使用可选的独立算法环境运行 PaDiM/PatchCore，用于数据与基线的早期检查。正式训练、模型部署、产线在线检测和多人协作不属于当前主流程。

首页的[数据集图书馆](anomaly-dataset-library.md)用于了解与获取公开工业异常检测资源；“我的数据集”继续管理本地项目。图书馆只提供介绍、真实预览及官方链接，不扩展为全学科门户或隐式下载/导入服务。

## 用户最短路径

1. **新建与扫描**：选择工业异常检测用途，填写名称并选择图片目录；未准备好目录时可稍后扫描。
2. **快速分拣**：判定完全 OK、临界、NG 或待定；不确定时先待定，不靠画框推进图像级流程。
3. **确认工件组**：同一工件的连拍和多视角归入同组，填写批次；规则先预览后确认。未分组的图片必须有真实的独立采集依据。
4. **选择交付方式**：要在工具内检查基线，进入“快速验证”；要交给独立算法环境训练，进入“划分与导出”。两种方式共用可信输入要求，不互相作为强制前置。
5. **检查后执行**：查看实际纳入、排除和阻断原因；快速验证先预览再运行，导出先检查再生成包。

只有正常图片时使用正常一致性探索，至少需要两个独立正常组，不给出异常检出率。独立评估要求纯正常训练组，验证和测试各有独立正常/异常组；不能复制图片或拆工件凑比例。

结果页先在验证集查看分数、热图与误报漏检，明确冻结阈值后开启测试。需要核对的图片显式加入人工复核；模型预测不会自动替换人工判定，当前改判也不重写历史实验。

**第二批从原实验继续**：扫描新批次、确认工件与批次，在原实验冻结阈值后选择“用此模型验证新批次”。沿用同一模型、ROI、阈值及热图标尺，只预测、不重新拟合；与已有输入重叠的内容或采集组按规则排除。未知人工真值不计入正确率或误报漏检分母。

## 功能取舍

以下判断依据当前任务关系和入口重复情况，尚无真实用户使用率统计，不能把“次要”直接解释为“无人需要”。

| 处理 | 功能或入口 | 判断依据与边界 |
| --- | --- | --- |
| 核心保留 | 扫描、分拣、工件分组、数据检查、严格划分与训练包 | 直接决定数据能否使用及评估是否可信；应有稳定、可发现的入口。 |
| 核心保留 | 快速验证、结果回看、人工复核、同模型新批次 | 构成从数据准备到发现问题、验证复用的闭环。 |
| 核心保留 | 任务状态、取消/重试、备份恢复、文件修复 | 平时低频，但支撑长任务和本地数据安全，不能按点击频率删除。 |
| 优先删除重复入口 | 同一管理区域中重复的分拣目录导出和旧目录映射按钮 | 详情页与“其他操作”曾同时调用相同回调，没有增加能力，只增加选择负担；每项保留一个清楚入口即可。 |
| 下沉到补充设置 | 新建时的负责人、来源、模态、许可、项目归属和可选标注方式 | 工业首批整理无需填写这些字段；保留编辑能力，默认突出名称、用途和图片目录。 |
| 下沉到管理或高级选项 | 普通标签管理、元数据导入、manifest/CSV、快照及复杂组合筛选 | 有明确研究用途，但不应与工业“下一步”争主操作；活动筛选必须可见并可清除。 |
| 按任务显示、保留兼容 | 几何标注、画笔拟合、SAM、LabelMe/COCO/YOLO/VOC | 已有独立标注数据和交换流程；不作为工业必经步骤。删除实现前需确认使用需求、历史数据读取和替代导出路径。 |
| 暂不扩展 | 在线模型服务、训练调度、云同步、团队权限、向量数据库、复杂 mask 编辑 | 不解决当前首批交付与第二批复用的关键问题；先取得真实用户验收证据，再独立评审。 |

不建议本轮直接删除任何后端能力或历史数据字段。最有把握的减法是删除重复入口、收起非必要表单、按任务组织功能。若后续要停用一项能力，应先记录谁需要它、替代路径是什么、旧数据如何读取，再明确停止入口或移除实现的范围。

## 界面与新增需求的约束

- 一屏内的主操作反映当前建议下一步；扫描、分拣、分组和验证不同时以同等强度争夺注意力。用户仍可主动进入其他阶段。
- 白底、浅边框、统一间距和按钮高度；颜色用于问题与判定，避免给普通管理功能分别配色。
- 工业主页先展示数据准备状态和图片，低频统计、普通审核及配置按需展开。不要让“分类未完成”被误认成工业判定未完成。
- 折叠只能降低信息密度，不能隐藏活动筛选、未保存修改、阻断原因、失败或任务进度。
- 新功能必须能说明帮助用户完成哪一步、是否已有相同入口、是否需要新增必填项。不能说清时，先放入候选池。

## 内容指纹与校验边界

- 常规流程不应要求用户理解 SHA-256 或反复确认校验。整包 hash 对交付核对有用；逐图指纹在后台服务于精确重复与跨集合/跨批排除，二者用途不同。
- 扫描已根据大小与修改时间复用旧指纹，重复图片分组也使用数据库值，无需额外读取图片。
- 新批次在同次预检只检查一次图片；只读质量检查仅解码图片计算指标，以文件大小/修改时间等信息提示过期或处理中变化，不承担逐字节完整性校验。
- 验证输入复制时同次流式核对内容；算法运行后不再重读原目录。复制后原目录独立变化不否定基于冻结副本的结果，复制前的变化仍会拒绝；项目判定/分组版本检查继续保留。
- 工业导出复制时校验一次，不再重读目标图片或逐个解压 ZIP 成员重算指纹。ZIP 保留名单/大小和整包校验；独立读取器在同次完整检查中复用已核对的样本行。
- 结果 JSON 使用同次读取的字节核对和解析。样本侧栏、扫描计数、重复组标题不展示摘要串；精确重复筛选用可清除的人类可读提示，快照及下载包的校验详情按需展开。
- 小 JSON 计划摘要和缓存键开销很小，不为“删 hash”改出一套新机制。若改为首次扫描完全不生成指纹，应同时设计重复识别、缩略图与历史输入兼容，不能只关闭扫描计算。
- 持久化指纹、计划和模型身份字段继续保留，历史数据不需迁移。测试应同时覆盖读取次数减少、复制前后源图变化、精确重复/跨批隔离与取消/失败不发布。

## 判断是否值得继续开发

优先观察真实用户能否独立完成首批交付和第二批复用，记录耗时、求助点、误操作及返工原因；合成示例和源码检查只能验证功能路径。
