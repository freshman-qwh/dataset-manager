# 工业数据快速验证实施计划 · 2026-10-30

本轮经用户授权，将本地数据准备扩展为数据准备、快速验证、失败样本复查及第二批复用。基础应用保持轻量，算法在独立环境和独立进程运行，原图不改写。旧 IA0–IA5 的严格训练包继续保留。

## 阶段与完整用户路径

| 阶段 | 实现 | 验收出口 |
| --- | --- | --- |
| Q1 主流程与分组 | 动态下一步、准备程度、简化高级选项、文件名工件规则及保存复用、任务下一步 | 从未扫描到完成分拣，入口始终指向可执行操作；新批次可复用工件提取规则 |
| Q2 独立验证执行 | 可检测/选择/创建 CPU 算法环境；固定 Anomalib 2.7.0；PaDiM 与 PatchCore；冻结输入、后台取消/重试及历史 | 运行真实预训练基线并产生可核对样本分数，基础应用不导入训练框架 |
| Q3 可理解结果 | 稳定结果页、原图/热图/正常参考、错误筛选、验证集阈值、冻结后测试及结果报告 | 每个指标可点到实际图片；阈值改变不修改人工真值和旧评估 |
| Q4 复查与第二批 | 候选加入人工复查队列；同一模型/预处理/阈值验证新批次；历史快照和批次统计 | 从错误图片进入分拣，处理后回到原实验；第二批不重新拟合模型或调整旧阈值 |
| Q5 ROI 与数据体检 | 单矩形归一化 ROI、热图映回原图、亮度/清晰度/近重复候选；原图只读 | ROI 随模型固定用于后续批次，质量候选人工判断，不自动删图或改标签 |

各阶段更新 TODO、CHANGELOG、ACCEPTANCE_TESTS；针对风险测试、前端构建、实际浏览器操作后单独 Git commit，不推送。

## 数据与评估规则

- 正式评估复用已冻结的严格 anomaly 计划：纯正常 train、组与精确 hash 传递隔离、val/test 两类覆盖。禁止为了通过验证重分已有测试集。
- 正常一致性探索允许仅正常数据：至少两个独立正常采集组，整组分为拟合和验证，给出正常误报/分数分布，异常检出率显示“无异常真值，无法评估”。它不生成“独立正式测试通过”的结论。
- 输入冻结包含 sample ID、hash、分拣真值/标准、组、split、图像大小、模型配方、ROI。算法 worker 读取应用管理的副本，发布前核对源文件、数据版本及输出。
- 训练模型只拟合 normal train。像素热图是模型输出；无像素真值时不计算像素指标，也不创建伪掩码。
- 验证集用于阈值选择。初始阈值有明确来源（有两类时验证 F1，只有正常时正常分位数），用户能在验证集调整。
- 用户明确冻结阈值后才解锁测试结果。记录测试内容 hash 已被查看的历史；重复使用测试图片显示开发参考提示。修改数据/ROI/阈值产生新结果，不重写旧实验。
- 误报/漏检只对有有效人工真值的图片定义，未知标签只展示预测。模型异常分数不是置信概率。
- 第二批必须使用原模型、图像处理和冻结阈值；同采集组/相同内容与旧训练/评估的交叉需提示并排除正式独立评估。

## 工程边界

- 不增加云、账户、在线推理服务、分布式训练或自动调参。默认串行 CPU，使用已有本地后台任务承载外部 worker。
- 独立环境可选择已有解释器；创建新环境需要可用 Python，安装范围和下载状态明确展示。首次权重缓存属于可选验证组件，支持离线已有权重。没有组件时仍可整理和导出数据。
- 采用已有正式迁移，增加运行记录、冻结阈值/测试曝光和复查元数据；大模型、热图、预测逐项结果放应用存储，不入 SQLite。
- 算法进程可取消；不完整或失配结果不发布为成功。只读查看结果不隐式开启训练、改真值或重新划分。
- ROI 首版只支持一个矩形，并随模型配方固定；不扩为复杂 mask 编辑器。近重复仅生成待复核候选。

## 端到端验收

1. 新项目扫描→分拣→文件名工件规则预览/确认→准备完成→快速验证；同一数据能继续导出原严格训练包。
2. 正常数据探索与两类正式评估各运行一次真实 PaDiM，PatchCore 也完成实际拟合/预测；核对输入 hash、样本集合及原图不变。
3. 热图与原图坐标一致，指标点击到图片，阈值只影响当前验证预览；冻结后的测试结果可追溯且不随滑块变化。
4. 结果→误报/漏检→人工复查→返回实验，旧运行保留原真值并提示当前判定已改变。
5. 冻结模型→新批次→同阈值预测；不重新训练，对重叠采集/重复内容明确提示。
6. ROI 运行与第二批复用一致；体检不改原图，近重复不自动合组或删除。
7. 失败/取消/进程中断/文件变化/缺组件路径可恢复；按阶段做浏览器和源程序验证。真实用户及干净 Windows 的定版证据仍独立保留。
