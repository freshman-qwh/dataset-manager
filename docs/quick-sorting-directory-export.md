# 快速分拣与目录导出：产品与开发设计

日期：2026-09-15
基线：v0.4.1；下一阶段候选版本：v0.5.0
状态：快速分拣主流程、可配置层级与普通目录/ZIP 导出已实现，Q1/Q2 补齐项和异常检测训练模板继续按 [TODO](../TODO.md) 推进。

## 1. 产品目标与范围

为收到一批客户图片的研究者提供“扫描 → 快速判定 → 分类复查 → 导出真实图片目录 → 运行现有算法 → 按需精细标注”的工作流。一次扫描登记的样本始终复用同一 ID，不因分拣、导出或进入标注而复制数据库样本。

第一条交付链路是快速分拣与普通目录导出（Q1–Q3）。异常检测训练模板与分组划分在 Q4；真实用户验证在 Q5。模型推理、预测导入和团队协作是后续范围，本阶段不安装模型依赖、不建设 GPU 服务。

产品原则：

- 分拣是所有受支持图片数据集的通用能力，独立于 detection/segmentation/classification 任务类型。
- 合格判定、OK 等级、缺陷类型、严重程度、精细标注进度、审核状态、split 分别表达，不混用。
- 高频操作只需一个判断；类型和程度可选填，不能为完整表单牺牲快速分拣效率。
- 原始图片只读；目录导出显式复制到新的输出目录，绝不隐式搬移或覆盖源文件。
- 保留 v0.4.1 的标注、快照、筛选和任务机制，小步扩展，不重做整套平台。

## 2. 分拣语义

### 2.1 独立维度

| 维度 | 值 | 规则 |
|---|---|---|
| 分拣判定 `triage_status` | `untriaged / pending / ok / ng` | 未分拣、待确认、合格、不合格；单选 |
| OK 等级 `ok_grade` | `clear / borderline / null` | 细分 OK 时必选；统一 OK 时为 null |
| 整图缺陷程度 `defect_severity` | `mild / moderate / severe / null` | 轻微、中等、严重、未评估；不是合格概率 |
| 缺陷类型 `defect_type_ids` | 类型 ID 集合，可为空 | 可选一个或多个类型，可只选粗类别 |
| 主缺陷 `primary_defect_type_id` | 已选类型之一或 null | 多缺陷按类型导出时明确唯一归属 |
| 分拣备注 `triage_note` | 可空文本 | 例如“客户允许的边缘擦伤” |
| 判定依据 | 数据集分拣标准版本 | 记录采用的客户标准，不从严重程度推断 OK/NG |

“未评估”不等于“无缺陷”，“待确认”不等于“勉强 OK”。严重程度属于整张图片，本阶段不记录每种缺陷各自的程度；区域级和逐缺陷程度以后按需要扩展。

组合示例：

| 图片 | 判定 | OK 等级 | 类型 | 程度 | 解释 |
|---|---|---|---|---|---|
| 无可见异常 | OK | 完全 OK | 空 | 未评估 | 适合作为正常训练候选 |
| 可接受的浅划痕 | OK | 勉强 OK | 划痕 | 轻微 | 符合客户标准，但不能默认混入纯正常训练 |
| 很小的关键区裂纹 | NG | 空 | 裂纹 | 轻微 | 轻微也可能不合格 |
| 明显异常，类型未知 | NG | 空 | 空 | 严重 | 允许只按程度分拣 |
| 同时划痕与污渍 | NG | 空 | 划痕、污渍 | 中等 | 类型和程度同时记录 |
| 是否可接受尚无结论 | 待确认 | 空 | 污渍 | 轻微 | 保留观察，但不进入正常训练 |

### 2.2 数据集层级配置

分拣标准新增两个稳定配置字段：`split_ok: boolean` 和 `ng_grouping: none / defect_type / severity / defect_type_and_severity`。默认值保持第一版行为，即细分 OK，并同时记录 NG 类别和程度。旧数据库中的策略 JSON 没有这两个字段时由 schema 默认值补齐，不需要迁移或改写历史 JSON。

层级配置是分拣输入、校验、筛选、统计与目录导出的单一依据。修改配置递增标准版本，已有判定原样保留并进入待复核；系统不批量删掉旧的等级、类别或程度。读取历史数据和生成兼容目录时仍可看到这些字段，新提交则必须符合当前配置。

### 2.3 校验与修改规则

- 细分 OK 时必须选等级；统一 OK 时禁止提交等级、缺陷类型或程度。NG、待确认、未分拣不能残留 OK 等级。
- NG 只接受当前 `ng_grouping` 启用的字段；未启用类别/程度时，对应提交和筛选都返回 422。
- 完全 OK 不允许有效缺陷类型或非空严重程度；发现这些字段时 UI 明示清空选项或改选勉强 OK，服务端拒绝矛盾组合，不静默丢失数据。
- 勉强 OK、NG、待确认允许类型与程度独立留空。勉强 OK 配严重缺陷给出提醒，但不代替客户标准自动改判。
- 未分拣不保留有效缺陷字段；“重置分拣”明确显示将清空的字段并提供单步撤销。其他通用标签、标注、备注和 split 不受影响。
- 主缺陷必须在已选类型中。选一个类型时可自动设为主缺陷；选多个时由用户指定，未指定允许保存，但按类型导出前必须处理。
- 缺陷类型允许两级“粗类/细类”，选择粗类也是合法结论。选择细类不自动新增父类关联；筛选父类可包含后代，统计按样本去重。
- 历史 `OK/NG` 普通标签不能直接回填分拣结论。通过映射预览显式迁移；仅有 `ok` 的旧目录必须明确映射为完全或勉强 OK，不能默认当作纯正常。
- 严重程度不决定 split，不改变审核状态；保存分拣不把几何标注标为完成，不自动确认“无目标”。

## 3. 页面与操作流程

### 3.1 入口与工作区

数据集详情页增加“快速分拣”入口，与已有“继续标注”并列在明确的工作模式区域；首屏根据最近模式突出一个主操作。新图片数据集默认引导分拣，已有标注队列保持原有继续入口。

新增 `/datasets/:datasetId/triage`，页面结构：

```text
顶部：返回数据集 | 队列范围 | 已判定 / 待确认 / 未分拣 | 保存状态
中部：大图（适配、缩放、平移、原图查看） | 缺陷类型与主缺陷
                                        | 程度、备注、判定标准
底部：完全 OK | 勉强 OK | NG | 待确认 | 跳过 | 撤销上一笔
```

图片区域复用已有预览、缩略图和原图接口；不直接复制包含绘制行为的 AnnotationPage。只抽取两页确实需要的图片加载、适配和有界预取逻辑。

### 3.2 快捷操作

- 建议默认按键 `1` 完全 OK、`2` 勉强 OK、`3` NG、`4` 待确认；空格跳过；`Ctrl+Z` 撤销上一笔。输入框、弹窗、中文输入法组合输入中不触发分拣快捷键。
- 统一 OK 时动作收缩为 `1` OK、`2` NG、`3` 待确认；详细表单、统计卡片和“全部图片”筛选同时隐藏未启用的维度。
- 默认“仅判定”模式：按键提交一个明确判定，保存成功才推进；NG 可暂不选类型和程度。
- “详细分拣”模式：点击判定先保留当前图片，在右侧选类型/程度，按 Enter 或“保存并下一张”提交；模式切换显式可见。
- 类型和严重程度默认不继承上一张；可提供会话级“沿用当前缺陷预设”，必须持续显示预设条，不能把旧值静默带给新图。完全 OK 不应用缺陷预设。
- 快速连按期间锁住当前提交；失败保留图片和草稿，不推进、不计完成。网络超时后先读取服务端状态再决定重试，避免重复推进。
- 预览未加载或原图无法读取时禁用判定；错误样本仍可在异常文件列表定位。提供足以判断细微缺陷的原图缩放，不能只依赖小缩略图。

### 3.3 队列、恢复与撤销

- 队列来源：未分拣、待确认复查、当前筛选、当前 split；分别显示范围和剩余含义。原有几何标注 `all_pending` 不直接套给分拣。
- 待确认记为“已查看但未判定”，从未分拣队列移出，进入待确认队列；跳过不改变数据库判定。
- 保存后当前图可能不再匹配队列。使用保存前稳定排序游标及样本 ID 找下一张，必要时环回；不能先套新过滤再按旧页码推进。
- 稳定排序初版提供文件名、相对路径、创建时间加 ID，不提供随分拣更新而跳动的 `updated_at` 默认排序。
- 刷新/重开恢复数据集、工作模式、筛选、游标和最后样本 ID；恢复前重新校验服务端状态。零条、末尾、样本删除和筛选失效都有明确空状态。
- 单步撤销恢复上一笔单样本判定与缺陷字段，使用提交后的 `triage_version` 做比较更新；出现后续修改则拒绝覆盖并提示刷新。撤销也递增版本，不能把版本号倒退。
- 第一版撤销仅承诺当前浏览器会话内上一笔，不承诺刷新后操作历史；批量修改先预览，完成后给出受影响范围，不冒充可一键撤销。

### 3.4 网格与批量

- 样本卡片显示判定/OK 等级；严重程度和类型在详情或紧凑摘要中展示。
- 筛选增加判定、OK 等级、程度（含未评估）、类型、主缺陷缺失；保存视图记录分拣工作模式及新条件。
- 批量操作第一版限制 200 个已选样本。请求明确各字段的保留/设置/清空和缺陷类型的追加/替换/清空，禁止把“没填写”当成清空。
- 预览展示变更与冲突数量；确认写入采用单事务和样本版本检查，任一冲突整批不写，返回具体冲突样本。不支持首版“全量筛选无限批量”。

### 3.5 旧目录映射（已实现）

数据集详情提供“映射旧目录”向导，按已扫描图片的直接父目录分页聚合。用户逐目录明确选择 OK、NG、待定或不导入，字段随当前 `split_ok` 和 `ng_grouping` 配置变化；细分 OK 时不允许缺少等级。默认只填未分拣样本，覆盖已有判定必须显式选择。

预览计划冻结 dataset revision、配置版本、样本 triage version、文件 hash 和目标字段；后台任务二次校验后在单个 SQLite 事务中写入，任一冲突整批回滚。目录名称建议只生成草稿，不自动提交、不创建缺陷类型、不操作原始文件。完整设计与验收见 [旧目录映射设计](triage-directory-mapping.md)。

## 4. 目录导出

### 4.1 范围和两种交付方式

独立“导出分拣目录”向导：选范围与交付方式 → 选择是否纳入待定/未分拣/过期判定 → 查看目录、数量、容量、排除原因及文件映射 → 创建后台任务。目录模板直接来自数据集分拣层级，用户无需重复配置。

- 范围为全数据集、当前筛选、当前 split 或明确已选样本；在任务开始前冻结具体样本集合和元数据。
- 首版同时提供两种交付：服务器托管新目录，以及包含相同目录结构的 ZIP 下载。
- 目录路径属于后端所在机器。远程访问时明确“写入服务器目录”，不能把浏览器电脑的路径直接传给服务器解释；需要带回本机时下载 ZIP。
- 默认新建唯一命名的运行目录，不合并、不覆盖已有目录；仅复制图片，不提供移动、硬链接或软链接。

### 4.2 普通分拣模板（Q3）

数据集层级配置直接选择固定模板，不做任意字符串路径表达式编辑器：

| 模板 | OK 路径 | NG 路径 | 适用场景 |
|---|---|---|---|
| 按判定（默认） | `ok/clear`、`ok/borderline` | `ng` | 第一轮粗分 |
| 按缺陷类型 | 同上 | `ng/<primary_defect>` | 按 defect 建目录 |
| 按程度 | 同上 | `ng/mild`、`ng/moderate`、`ng/severe`、`ng/ungraded` | 只看缺陷轻重 |
| 类型 + 程度 | 同上 | `ng/<primary_defect>/<severity>` | 两个维度都有需求 |

OK 下缺陷类型仍保存在 manifest，不把勉强 OK 的瑕疵混入 NG。关闭 `split_ok` 后导出到统一 `ok/`；开启后使用 `ok/clear`、`ok/borderline`，历史无等级 OK 进入 `ok/ungraded`。每张样本的 manifest 提供规范 `export_bucket`，统计、预检、目录和 ZIP 使用同一个 `configured_export_bucket` 算法。

```text
customer_batch_export_<run-id>/
  ok/clear/101__a.png
  ok/borderline/102__b.png
  ng/scratch/mild/103__c.png
  ng/unknown/ungraded/104__d.png
  pending/105__e.png
  untriaged/106__f.png
  manifest.jsonl
  export-config.json
  export-report.json
```

未分拣和待确认默认不复制，但必须在预览、清单和报告中计数；用户可选择放入独立目录。不能将排除项静默计为导出成功图片。

多缺陷策略首版固定为“一图一份”：

- 无类型的 NG 放 `unknown`；程度为空放 `ungraded`。
- 多类型有主缺陷，按主缺陷落目录，清单保留所有类型。
- 多类型无主缺陷进入 `multi_defect`；用户后续补主缺陷再预检时会进入该主类型目录。
- 本阶段不支持复制到每一个 defect 目录，避免重复计数和训练泄漏。
- 目录名使用稳定类型 ID 加安全别名，报告提供 ID、显示名称、父类映射；类型重命名不破坏历史导出。

### 4.3 异常检测训练模板（Q4）

普通分拣导出与训练划分分开。Q3 不宣称输出已满足训练协议；Q4 新增可验证的异常检测模板。

- `train/good` 默认只含完全 OK；勉强 OK 默认排除，用户可明确纳入验证/测试正常集，计数及配置单独记录。首版不开放勉强 OK 进入训练。
- NG 只进入 val/test，未分拣和待确认不能纳入训练数据。
- “使用现有 split”先校验，非法组合阻断且不偷偷修正；“生成划分建议”只作用于本次导出计划，用户另选“写回 split”才修改数据库。
- 分组键以实际采集信息为准，提供批次内工件/采集组字段和导入映射；仅有客户批次不等于同一工件。分组后固定 seed，组内图片不可跨 split。
- 相同 SHA-256 样本必须同组或由用户明确排除重复；同组同时包含 OK/NG 时整组不能进入纯正常训练。不得为凑比例拆组。
- 样本或组太少无法满足 val/test、正常/异常覆盖时给出阻断原因；允许显式 train+test 的受限方案，但说明没有独立验证集时不能用 test 调参后声称独立评估。
- 最终测试集不参与阈值选择。输出 split 分配、组映射、排除原因、seed 和规则版本。
- 先适配一个固定版本的 Anomalib Folder 读取链路，用真实导出产物运行数据加载烟测；不把“文件夹看起来正确”当成适配通过。
- 无 mask 的 NG 是合法图像级异常样本；不能输出全零 mask 冒充已标注，也不能据此计算像素级评价。复杂 mask 编辑不进入本阶段。

### 4.4 预检与冻结契约

预检返回分页的目录树、选中/纳入/排除/冲突样本数、字节估计、文件名映射、告警及阻断原因。计划产物冻结以下内容：

- 数据集 ID、revision、分拣标准版本、具体样本 ID、源相对路径、源 hash、完整分拣信息与 split。
- 类型目录及显示名称、模板版本、排除规则、主缺陷策略、目标相对路径、输出介质与目标根目录。
- 配置/计划内容 hash、创建时间、失效时间和计划 ID；作业小参数只引用计划，不把十万样本塞入 jobs JSON。

预览计划在服务端应用存储生成，不写入 jobs JSON。当前实现冻结创建时读取到的具体样本及其源 hash；用户确认时重新核对 dataset revision、分拣配置版本和计划内容 hash，复制每个文件时再重算 SHA-256。扫描、导入或分拣与预检重叠而导致 revision 或源字节变化时，任务不会发布并要求重新预检。后续跨事务批量分拣仍需增加更强的运行区间冲突门槛。

用户确认时重新核对 revision、计划 hash、源身份和目标；计划过期或内容改变要求重新预览。任务创建后仅依冻结计划运行，后续人工改判不影响本次目录；重试仍使用同一计划，源 hash 不符则失败并要求重建计划。

每个源文件以只读流复制并同时校验 SHA-256，导出字节必须匹配计划 hash；缺失、读失败、字节变化、磁盘不足均让任务失败，不发布看似完整的结果。

### 4.5 路径与发布安全

- 输出父目录应存在、可写且位于配置的导出根目录白名单中；不得写入原始数据根目录、已登记扫描根目录内、数据库目录或内部缓存区域。应用托管 export 区域单独允许。
- 源目录之间与目标目录的包含关系按最终解析路径判断，覆盖 Windows 大小写、UNC、符号链接/junction；操作前再次核对，不以字符串前缀判定。
- 文件名采用样本 ID 加规范化原名，处理同名、大小写碰撞、Unicode、Windows 保留名、尾点/空格、超长路径、`..` 和分隔符。清单保留原始名称与输出名称对应关系。
- 目录模式在目标父目录创建仅属于该任务的临时目录；全部图片和报告写完校验后，在同一文件系统发布到不存在的最终目录。已有目标、竞争创建和跨盘搬运不可降级为覆盖/合并。
- ZIP 沿用现有单文件临时产物发布方式，包含同一清单与目录规则，条目路径同样校验；默认对已压缩图片使用低成本存储方式，避免无意义重复压缩。
- 取消/失败只清理任务登记并验证归属的临时目录/文件，绝不递归删除用户选择的父目录。重启后处理中任务标为 interrupted；清理失败保留可定位状态，不声称已清理。
- 文件系统发布和数据库成功状态不是同一事务：运行目录携带 run ID 与完成标记，重启时核对标记和清单恢复终态，不能因数据库更新失败重复复制或覆盖已发布目录。
- 成功目录归用户管理；删除任务记录/数据集不删除外部导出目录。托管 ZIP 按既有任务产物策略管理，前端显示已过期而非提供坏链接。

### 5.2 数据结构与迁移

采用可索引的结构化字段，不将核心分拣结论塞入任意 `metadata_json` 或普通字符串 tags：

- `samples` 新增 `triage_status`（默认 untriaged）、`ok_grade`、`defect_severity`、`primary_defect_type_id`、`triage_note`、`triage_version`（默认 0）、`triaged_at`、`triage_policy_version`、`triaged_file_hash`。缺陷类型改动也递增 triage_version。
- `defect_types` 新表：ID、dataset_id、name、parent_id、稳定目录 code、description、is_active。父类必须同数据集，最多两级、禁止循环；使用中的类型只停用不硬删。
- `sample_defect_links` 新表：sample_id + defect_type_id 唯一，校验同数据集。首版不复用普通 Tag 关系，防止客户名/整理标签混成缺陷；可复用现有管理组件的交互样式。
- `datasets` 新增有 schema 的分拣标准配置与版本：标准说明、完全/勉强 OK 定义、严重程度说明；不支持自定义脚本规则引擎。标准修改提升版本并提示旧判定需复查，不批量自动改判。
- `triaged_file_hash` 记录作出判定时看到的内容。扫描/重新定位发现内容 hash 变化，保留旧判定供复查，但显示“判定已过期”，默认不允许作为可信训练输入；仅路径改变且 hash 不变保持有效。
- 分拣可信条件同时检查内容 hash 与标准版本；Q3/Q4 预检均展示过期数量，Q4 训练导出阻断过期判定。
- 添加实际查询需要的 dataset+判定+等级/程度索引，以及关联表反向索引；用基准验证，避免盲目添加所有组合。
- 使用正式 Alembic 增量迁移，旧样本回填未分拣；不重建实际库、不执行启动时静默迁移。旧 tags、审核和标注字段保持原意。
- 删除样本/数据集的服务、完整性检测和备份校验需纳入新表与外键；外部导出目录不参与级联删除。

已有样本列表、统计、manifest、保存视图、快照 API 扩展分拣字段；所有返回使用 schema，不泄漏 ORM。统一分页与请求大小上限，核心筛选在 SQL 执行。

### 5.4 快照和导出清单

- 当前 `DatasetSnapshotContent.schema_version` 只接受 1；新增版本 2 读取分派，同时保留版本 1 原字节/hash 的验证与读取，不能补字段后破坏历史 hash。
- 旧快照的分拣显示“未记录”，不倒推为当时未分拣；新版差异增加 triage 变化类别。
- 新快照包含类型目录、标准配置和分拣结论；历史训练标签重建继续支持旧任务格式。
- 目录导出计划与通用快照共享规范化字段和 hash 规则，但不直接复用当前一次性加载所有样本/标注的快照构建方式。
- 大型导出使用分块或 JSONL 计划，job 参数只存计划引用与 hash；每次流式读写，图片不全量载入内存。
- `manifest.jsonl` 每行一个选中样本，含 sample_id、源相对路径、源 hash、分拣维度、类型列表、判定标准版本、split、exported/excluded 状态、目标相对路径或排除原因。默认不把源绝对路径放进可分享包。
- `export-config.json` 冻结规则和来源 revision；`export-report.json` 汇总数量、复制字节、hash 校验、排除原因和运行 ID。同计划与源字节得到相同映射及图片内容；不承诺含时间戳 ZIP 的二进制 hash 完全相同。

### 5.5 精细标注与后续模型扩展

分拣入口对现有三种任务均开放，不新增 task_type=anomaly。默认几何任务继续由数据集 task_type 控制：已有 detection/segmentation 可直接从分拣结果进入对应标注；classification 在首次进入精细标注时明确选择现有任务类型，复用原样本，保留分拣结果。存在不兼容几何对象的任务切换按原有校验阻断，不自动转换或删除对象。

缺陷类型与 annotation class 通过显式映射衔接；选择分拣缺陷不会自动生成框、多边形或正式 annotation class。

未来预测作为独立结果保存，引用数据计划/快照、sample_id+hash、模型版本与预处理配置，不直接覆盖分拣。模型运行在独立环境，通过接口连接；本阶段只保证清单与稳定身份可供其对接。

| Q5 | 真实用户试用 | 同批图片与资源管理器对照、记录失败路径、据数据决定扩展 |

Q1→Q2→Q3 是第一轮最小闭环；Q3 完成即可邀请用户试用，不等待模型或团队系统。Q4 仅在普通导出稳定后进入。每批独立提交和验收，首次实现后才更新 CHANGELOG/ACCEPTANCE_TESTS，未实现不勾完成。

必须覆盖的验证：

1. 语义：完全/勉强 OK、仅程度 NG、仅类型 NG、多类型、待确认、重置、标准变化、原图内容变化；不影响几何与审核状态。
2. 连续操作：至少 100 张混合图片，连按、中文输入、保存超时/失败、当前图出队、环回、刷新恢复、撤销冲突；统计与实际样本一致。
3. 目录：同名/中文/长路径/保留名、多缺陷无主类、空程度、未分拣排除、真实目录与 ZIP 清单一致，原图 hash/路径不变。
4. 故障：复制中改写源文件、磁盘不足、无权限、取消、任务重试、服务重启、目标竞争创建、发布后数据库更新失败；不留下可误认成功的半成品。
5. 训练：默认 train 只有完全 OK；NG、过期判定和待确认无法漏入；同工件/重复样本不跨 split；NG 无 mask 仍可加载为图像级任务。
6. 回归：旧库迁移、旧快照 hash、保存视图、原有几何队列和导出、数据库备份/完整性。按批次跑有意义的后端测试、前端构建、浏览器验收及 diff 检查。
7. 性能：10k/100k 数据只返回分页和有界邻居，导出内存不随全部图片字节增长；记录队列切换与保存推进 p50/p95。图片预加载后的保存推进 p95 目标 ≤300ms（注明硬件/图尺寸/是否计解码），未达到则定位而非虚报。
8. 用户价值：2–3 位目标用户在 3 分钟内完成首轮判定，能独立导出并运行现有读取脚本；比较相似难度分层抽取且交叉安排的图片批次，记录每百张耗时、误分修正、操作求助和第二批使用意愿，不设未经测试的“效率提升已达标”。
