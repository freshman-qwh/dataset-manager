# 快速分拣体验收敛规划

更新日期：2026-09-22

## 目标

让第一次使用者不读说明也能完成“选择记录粒度 → 连续判定 → 发现边界样本 → 修正 → 导出”的最短闭环，同时确保修改规则不会静默丢失既有信息或改动原始图片。

## 产品决策

### 1. 首次配置与再次修改

- 数据集尚未完成首次配置且全部图片未分拣时，进入快速分拣自动打开配置弹窗。
- 默认选中“统一 OK + NG 不细分”，这是工人、学生和初次使用者都能理解的最低认知负担方案。
- 首次确认即使沿用默认值，也记录“已完成首次配置”，以后进入页面不再重复弹出。
- 再次修改先请求服务端影响预览；有既有判定时必须二次确认，并显示待复核数量、保留的细分信息和需要补录的字段。
- 规则变化不会批量改写样本判定。已有样本按旧规则保留在 SQLite，并因规则版本变化进入待复核；在较粗规则下不再参与当前目录结构的细节，只有用户重新保存该样本时才按新规则清理不适用字段。

### 2. 术语与目录命名

- 工作区继续使用短而稳定的判定词：`OK / NG / 待定复看`。细分时使用“完全 OK / 临界 OK”和“轻微 / 中等 / 严重”，避免同一页面同时出现合格、正常、Pass、Good 等多套近义词。
- 目录名是交付格式，不与判定语义绑死。后续在导出向导增加命名方案：通用 `ok/ng`、质量 `pass/marginal_pass/...`、异常检测 `good/...`、自定义；不在快速分拣主操作区堆叠这些选项。
- 当前目录预览只展示本次规则会生成的主路径；`unknown/ungraded` 等兼容目录仅在真实旧数据存在时提示，不作为首次配置的固定说明。

### 3. 选项顺序和默认值

- “统一 OK”排在 OK 选项第一位，“NG 不细分”排在 NG 选项第一位，两者均为新数据集默认值。
- 精细模式继续保留，但使用解释性文案说明适用场景，而不是要求新用户先理解全部字段。

### 4. 旧目录映射的入口

- 旧目录映射本质是“导入已有组织方式”，首选入口应放在首次扫描/导入完成后的引导中；数据集详情保留可再次进入的管理入口。
- 不把完整映射向导塞进快速分拣工作区。快速分拣只在检测到“全部未分拣且存在明显目录分组”时提供轻量提示，用户主动选择后跳转向导。

### 5. 大数据量导航

- 保留上一张/下一张和键盘操作，新增可拖拽进度条、当前位置输入和“跳到第 N 张”。
- 拖动期间只更新位置提示，释放后再加载图片，避免大队列连续请求；输入值按当前队列范围校验。

### 6. 多步撤销

- 会话内维护最近 20 步成功判定，逐步使用现有版本/hash 条件写入撤销；遇到外部修改即停止在冲突项，不覆盖新数据。
- 不在本阶段实现跨设备或跨会话无限历史；刷新后仍以数据库现状为准。

### 7. 待定复看指引

- 队列选择由普通下拉框改为更显眼的分段入口，并在保存“待定复看”后提示去向和剩余数量。
- 当待定队列非空时显示带数量的“复看待定”动作；空队列则解释待定的用途，不让用户猜测结果去了哪里。

## 分批实施

### P0：首次流程和数据安全（本轮）

- 首次配置弹窗及简单默认值。
- 配置影响预览、二次确认和配置版本冲突保护。
- 旧库迁移：有历史判定但未存显式策略时，先固化旧精细策略并标记已完成首次配置。
- 细分到粗分保留历史细节，粗分到细分统计待补录字段；所有旧判定按新策略版本标记待复核。
- API、迁移、前端构建和浏览器人工验收。

### P1：连续操作效率（本轮完成）

- [x] 可拖拽/可输入的队列进度跳转；拖动只更新位置，释放、键盘调整结束或提交数字时才加载。
- [x] 会话内 20 步撤销；继续使用样本版本和文件 hash 条件写入，同图多次修改可连续回退，外部冲突停止且不覆盖。
- [x] 显眼的队列分段入口、实时数量、待定复看高亮，以及保存待定后的去向和快捷入口。

### P2：导入与交付命名

- 首次扫描后的旧目录映射建议入口。
- 导出命名方案与自定义目录名，不改变数据库内稳定语义。
- 仅在真实兼容数据存在时显示兼容目录说明。

## 数据安全不变量

- 快速分拣和规则配置只写 SQLite 元数据，不移动、重命名、覆盖或删除原始图片。
- 配置提交必须携带读取时的规则版本；版本不一致返回 409，用户刷新后重新预览。
- 修改规则不会批量抹除细分字段；重新保存单张图片时，服务端才按当前规则验证并规范化该图片的字段。
- 迁移前后，有历史判定的数据集保持原有目录解释，不因新默认值变化而被静默重分类。
