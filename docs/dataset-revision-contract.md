# 数据集 Revision 契约

## 目标

`Dataset.revision` 是数据集 SQLite 元数据内容的单调递增版本号，用来解释后续快照、缓存和训练产物基于哪一版数据。新建数据集从 `1` 开始；revision 不用于恢复历史，也不复制原始文件。

## 递增规则

一次成功的逻辑写操作最多递增一次。递增与业务写入位于同一数据库事务；业务事务回滚时，revision 也回滚。

会递增：

- 修改数据集资料或任务类型。
- 单样本/批量修改、修复、删除，以及 split 规划。
- 扫描新增样本、更新文件内容或状态、标记缺失样本。
- 保存标注、显式把标注类别同步为样本标签。
- 新增、修改、删除样本标签或标注类别。
- 同步或任务式元数据/LabelMe 导入，以及对应显式回滚。
- 保存训练准备配置。

不会递增：

- 只读预检、统计、质量、重复样本、manifest 和标注导出。
- 无内容变化的增量扫描；`last_scanned_at` 等观察时间不代表新数据版本。
- 任务创建、进度、取消、重试记录和任务产物下载。
- 缩略图生成/清理、SQLite 备份、导出产物记录和 `last_export_at`。
- 轻量快照创建、读取与下载；快照记录来源 revision，但自身是该 revision 的派生产物。
- 没有命中样本的批量请求、没有新增标签的重复类别同步。
- 数据集删除，因为删除后没有可继续引用的 revision。

## 分批与恢复语义

同一次执行即使分多批提交，也通过 `DatasetRevisionTracker` 最多递增一次。任务取消或失败后已提交的部分结果仍属于该次执行，保留已产生的 revision。用户显式重试或回滚是新的逻辑写操作；如果实际提交元数据，会各自再递增一次。

## 数据库与 API

- `datasets.revision` 为非空整数，默认值为 `1`，由 Alembic 正式迁移增加并为旧记录回填 `1`。
- `DatasetRead` 始终返回 `revision`；数据集详情页展示当前值。
- 所有递增必须通过 `dataset_revision_service`，业务服务不得各自实现计数逻辑。
- revision 只描述 SQLite 元数据版本。原始文件仍然只读；若磁盘内容在扫描前被外部修改，revision 不会提前猜测该变化。

## 后续依赖

E1B 轻量快照已记录 dataset id 与 revision，并冻结 manifest、文件 hash、标注、标签、split、class map、查询范围和导出配置。统计或预检缓存只有绑定 revision 后才可复用。
