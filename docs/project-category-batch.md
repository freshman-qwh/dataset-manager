# 项目、类别与批次

项目归纳业务，数据集保存一套持续积累的数据；对象类别描述产品或对象，批次记录哪次采集，文件夹只表示原始磁盘位置。普通标签继续用于反光、待复核、视角等可自由组合的信息；几何标注类别独立保留。

## 本地项目的导入

1. 首页“管理项目”创建探针、绿油锡等项目，新建数据集或在设置中选择所属项目。项目是可选归属，旧的未归属数据集可继续使用。
2. 在数据集“添加图片”选择目录，选择已有批次或新建批次；批次名称可用“首次采集”“补充异常”等，日期和备注可在“类别与批次”编辑。
3. “预览导入内容”核对数量、格式和识别警告，再开始扫描。一个批次可多次追加目录；不同批次也可位于不同磁盘位置。
4. 批次只赋给新增图片，重复扫描不会重新分配旧图片。需要调整时，在本地浏览勾选图片，进入“设置类别或批次”，只修改明确选择的字段；工件组和判定保留。
5. “管理类别与批次”可添加、改名、补充说明；被图片使用的记录不能直接删除。批次改名不会改变其稳定身份。项目改名同步旧的项目名称字段。

## 新批次接收方案

工业数据准备页的“接收新的采集批次”提供“批次接收方案”。方案用于同一数据集后续追加的图片，保存方案名称、导入格式、相对目录到已有类别的映射及文件名工件规则；现有分拣标准、参考卡和默认检测区域继续沿用。

1. 打开“批次接收方案”，设置目录前缀与类别，例如 `product` 指向通用类别、`product/probe` 指向探针类别。更长的匹配目录优先，根目录规则可填 `.`；不接受绝对路径、`..` 或重复目录规则。
2. 按需启用文件名工件规则。`part_001_camA` 以 `_` 分隔、保留前 2 段可得到 `part_001`；同一工件的视角应得到相同编号。确认后保存方案，修改未保存时先保存、放弃或取消再离开。
3. 点击“添加本批图片”，在原扫描入口选择“使用方案导入格式”，指定或新建采集批次并完成扫描。核对扫描实际报告的新增、更新、未变和缺失情况；重复扫描保留旧图批次与判定。
4. 返回“整理本次扫描批次”，选中已完成扫描的批次并点击“预览本批接收”。核对图片数量、未分拣、重复内容、未匹配、已有值冲突，以及逐行类别/工件原值与本次值。
5. 输入预览提供的完整确认文字后“确认接收并补充信息”。只填本批为空的类别与工件字段，不改采集批次、人工判定、split 或原图；已有非空字段与方案冲突时阻断本批确认，修改方案后需重新预览。

未匹配规则的图片可以保留空值并继续人工处理；重复内容只作为提示，不自动删图或合组。本批没有需补充的空字段时可直接继续分拣或交付检查。方案、数据版本或源图片变化会拒绝旧计划，成功的重复确认复用回执；界面刷新失败不等于接收提交失败。

方案保存在数据集已有 SQLite 元数据中，轻量数据库备份包含方案；工作区 ZIP 还包含接收冻结计划及回执所需元数据。原图不包含在这些备份中，换位置后仍需单独挂载。此流程不跨数据集复制标准、判定或模型，也不改变已有实验。

## 类别与目录浏览

- 本地浏览左侧按项目筛选数据集；右侧类别卡片展示封面、数量与正常/异常统计，批次下拉用于采集范围切换。
- 类别或批次筛选默认跨来源平铺查看，避免新批次在其他目录时被旧来源遮住；也可选择具体来源再按文件夹浏览。同名物理目录不合并为一棵虚假目录树。
- 类别、批次和普通标签相互独立。任意目录名不会自动变成类别；普通图片通过显式管理赋值。

## MVTec AD 与 VisA

- 自动识别 MVTec AD 整套/单类别布局：类别目录下 train/good、test/good 或缺陷目录，以及 ground_truth 中对应 mask。
- VisA 支持原始 Data/Images、Data/Masks 布局以及官方转换后的 1cls 布局。优先读取本地 split_csv/1cls.csv，否则使用随软件附带的官方单类划分索引；来源及许可见 [索引说明](../backend/app/data/visa/README.md)。不匹配的图片不会编造官方划分。
- 新图片写入对象类别、官方 train/test、官方正常/异常真值与 mask 关联；官方真值用于初始化新图判定。没有官方 val 时不自动制造验证集。
- mask 不作为新图片样本登记；大图预览可勾选“显示官方 Mask”，非零区域半透明着色。原 mask 只读，不转成几何标注，不自动生成像素指标。
- 已登记图片默认保留原信息。导入格式中可勾选“为已有图片补充识别信息”，仅填空的类别、官方划分、来源真值和 mask 关联；现有人工判定、实际 split、工件、批次及非空语义字段不覆盖。
- 缺失/尺寸不一致的 mask 给出警告且不关联；异常图片不被当作空 mask。旧库曾登记的 mask 图片记录保留，不自动清理。
- 官方划分单独保存，后续人工实际 split 可独立管理。当前基线按单一对象类别运行，官方 test 不得进入拟合；导入和浏览成功不等于完成官方 benchmark 评测。
