# 工业异常检测试用指南

目标是把本地工业图片整理成可复核、工件隔离、可被算法读取的图像级异常检测数据包。训练和模型评估仍在算法环境运行。

## 第一次体验

1. 首页点击“体验合成示例”，熟悉完整流程；合成图片只用于操作练习，不代表算法效果。
2. 自建项目选择“工业异常检测”，扫描本机图片。无需先打标签或画框。
3. 快速分拣：完全 OK 是纯正常候选，临界 OK 默认排除，NG 是异常，拿不准的先待定。规则或文件变化后需要复核。
4. 填写工件和采集批次。同一工件的连拍、多角度图片属于同组。按父目录生成的只是草稿；按 OK/NG 分类的目录不能直接当工件。CSV/JSON 可按相对路径映射列，先预览再确认。
5. 点击“准备异常检测数据”。检查整组划分、实际数量与排除原因。缺组时必须补充组或明确声明独立采集；默认不写回项目 split。
6. 完整协议需要正常 train，且 val/test 各有正常与异常图片。图像级默认正常建议 80/10/10、异常建议 0/50/50，组独立性优先。小数据不够时补数据，不复制图片凑数。
7. 生成 ZIP 或本机目录，按包内 README 在独立环境运行 `load_anomalib.py --check-only`，再完整读取。不要重新随机划分，不用 test 调参。

当前试用边界：每个工业协议项目最多 10000 个登记文件；图像级协议不生成像素掩码，不提供像素级指标。不要将读取通过描述为模型精度或产线效果已验证。

## 备份、恢复和原图迁移

首页“数据库维护”提供两个备份范围：

- 元数据与快照 ZIP：SQLite、引用的快照、冻结计划、任务恢复元数据，含逐文件 hash 和表计数。其他后台任务结束后创建；备份过程中若数据变化会拒绝发布。
- 轻量 `.db`：仅 SQLite，不含外部快照文件。

两者都不包含原始图片、缩略图或历史下载产物，原图与需要保留的训练包请另行备份。元数据 ZIP 当前上限 20000 个文件、2 GiB。

恢复 ZIP 时先在页面“校验并恢复元数据 ZIP”恢复到新的应用管理目录，或在源码环境执行：

```powershell
cd backend
.venv/Scripts/python.exe -m app.cli.workspace --archive '备份.zip' --target-dir '一个尚不存在的新目录'
```

程序逐文件校验、检查 SQLite 结构/关联/计数及快照内容，全部通过后才发布新目录。不会覆盖正在使用的工作区。当前版本恢复需匹配数据库迁移版本；旧版本备份应先用对应版本恢复再按维护流程升级。

便携版安全退出后，可以指定恢复位置启动：

```powershell
& '.\DatasetManager.exe' --workspace '恢复完成的新工作区目录'
```

此参数只接受含恢复报告和数据库的目录。仍使用单实例限制；再次打开同一恢复工作区时使用同一参数。双击默认程序仍打开默认工作区。

源码版先停止原服务，明确设置新位置的 `DATABASE_URL=sqlite:///绝对路径/database/app.db` 和 `STORAGE_ROOT=绝对路径/storage` 后启动。检查后台 `.env` 不覆盖这些设置。

原图在另一位置时，在项目设置使用已有目录修复流程：选择新原图根目录、检查匹配预览、再确认元数据路径变更。它不搬动或改写原图。快照保留原始历史路径，不补写当前值。

## 试用验收记录

本机工程验收覆盖分组、划分、导出读取、备份恢复及故障路径。正式试用仍需要独立干净 Windows 10/11 环境，以及 2–3 位工业目标用户用各自两批真实数据完成流程，记录首次交付时间、每百张操作时间、求助与修正次数；至少两人独立复用后再判断是否达到定版。
