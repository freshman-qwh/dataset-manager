# 工业异常检测：试用定版修改计划

日期：2026-10-29
状态：规划，功能尚未实施；不代表验收通过或新版本发布。
依据：[本轮验收报告](acceptance-review-2026-10-29.md)、现有分拣/目录导出能力及用户明确的工业异常检测定位。

## 1. 首版产品承诺

面向个人研究者及工业视觉研发人员，将本地采集图片整理为**纯正常训练、验证与测试相互独立、可追溯并可直接加载的异常检测数据包**。

首版聚焦基于正常样本训练的图像级异常检测。已有检测/分割标注作为可选的缺陷定位能力保留，不要求用户先画框或多边形。应用负责数据准备，训练继续在用户的算法环境中进行。

交付主流程：

```text
创建工业异常检测项目
  → 扫描图片 / 导入已有目录判定与采集分组
  → 完全正常 / 临界可接受 / 异常 / 待定
  → 复核过期判定、坏图、重复及分组
  → 预览纯正常训练与独立验证/测试方案
  → 生成数据包
  → 在固定版本读取器中核对实际加载结果
```

第一版约束为一个数据集对应一种产品/规格及已明确的成像条件。跨产品、多工位、多模型编排后置；采集批次和视角信息可以登记，但不据此自动推断跨域泛化能力。

本计划成为工业异常检测后续开发的活动依据。原 Q1–Q3 的已实现能力继续复用；原 Q4 的 Folder 读取设想调整为“显式保留划分的读取适配”，技术原因见第 6 节。

## 2. 必须改变的现有逻辑

| 现状 | 计划修改 | 验收重点 |
|---|---|---|
| 创建时先选检测、分割或分类 | 新增工业异常检测用途，几何标注方式置于可选设置 | 新人不需要为图像级判定选择标注工具 |
| 详情页主进度来自几何标注或样本标签 | 工业模式按分拣、待复核、训练候选和协议准备情况显示进度 | 不画框、不补普通 tags，也能完成异常检测准备 |
| 训练划分只接收已完成标注的检测/分割图片 | 新建异常检测协议入口，候选依据有效分拣结论和组约束 | 不修改原有监督检测/分割导出语义 |
| 通用随机比例与精确重复分组 | 正常与异常分别分配；工件/采集组和精确重复共同限制 | 异常不能进入 train，关联图片不能跨 split |
| 普通 ok/ng 目录即可交付 | 主交付为带划分、清单、规则、加载说明的异常检测包 | 下游实际加载集合与预览逐项相同 |
| 轻量快照不记录分拣 | 快照 v2 纳入判定、标准、分组及协议引用 | OK→NG、分组改变都能看到差异 |
| 备份以数据库下载为主 | 补充经演练的恢复流程及必要外部元数据工件 | 恢复后判定、分组、标注及历史快照可核对 |

## 3. 领域规则：合格、纯正常、异常分别表达

### 3.1 工业模式默认判定

新建工业项目默认启用 OK 两级：`完全 OK` 与 `临界可接受`；NG 默认不强制细分。缺陷类型、程度、备注均可后补，单键判定继续复用现有工作区。

- **完全 OK**：按当前判定标准，没有需要排除出正常训练分布的异常，可成为纯正常训练候选。
- **临界可接受**：业务上可能合格，但存在偏差或瑕疵。默认不进入训练、验证或测试；人工明确选择后，仅可作为单独记录的 val/test 正常样本。
- **NG**：异常图片，只能进入 val/test；有无缺陷类型和像素标注不影响图像级使用资格。
- **待定、未分拣**：不进入异常检测数据包；可随普通整理导出另行交付。
- **过期判定**：原图 hash 或判定标准版本不一致，重新复核后才能进入协议。
- **不可读取、不可解码**：不纳入有效候选，必须给出排除原因。

训练候选还要通过组约束、文件校验及排除规则；“完全 OK 数量”不直接等于“最终 train 数量”。

### 3.2 旧数据和统一 OK

现有数据集不自动切换工业模式，不改变既有 task_type、split、标签或标注状态。工业用途通过新字段 `workflow_profile=industrial_anomaly` 表达，旧数据默认 `general`。

工业模式与 `task_type` 分离：前者决定准备目标，后者继续决定可用几何工具。新建工业项目默认只做图像级整理；开启缺陷定位时选择现有检测/分割方式，不把分类 tags 当成异常判定的替代物。

旧项目的 `ok_grade=null` 仅表示统一 OK，**不自动推断成完全正常，也不显示为临界 OK**。用户可继续普通目录导出；进入严格异常协议前，先预览开启等级的影响，再明确选择和复核图片，使用已有批量预览/事务确认设置等级。不能通过一次“把全部 OK 当正常”的隐藏选项绕开复核。

不因为“无可见缺陷”或图像级 OK 自动写入 `completed_empty`：几何标注进度保持原语义。

既有审核状态不自动转换为分拣结论。历史已拒绝样本先列入待核对清单并默认排除；若拒绝原因仅为几何标注问题，用户复核图像级判定后，可在本次方案中显式确认纳入，记录样本、原因、hash 和标准版本。不能静默忽略拒绝，也不能以补完几何标注或几何审核作为图像级准备的隐式前置条件。

## 4. 分组和防泄漏

### 4.1 最小元数据

第一版新增结构化 `capture_group_id`（工件/关联采集组）和可选 `capture_batch_id`（采集批次）；同一数据集内用 `(capture_batch_id, capture_group_id)` 标识用户声明的组。字段不复用标注对象的 group_id；批次本身不等于工件组。两者先使用有长度限制的文本字段与索引，不引入额外的工单管理体系。

支持三种录入：CSV/JSON 显式列映射、按目录/文件名生成分组草稿、选择图片批量设置。草稿必须先展示示例、组数、跨旧划分影响，再明确确认；不在扫描时悄悄把同目录全部视为同一工件。

缺分组时，用户选择“补分组”或明确声明“这些图片独立采集”。后一选择及其适用范围写入导出计划，才允许按单图独立分组。默认未知状态不能直接声称已防止工件泄漏。

### 4.2 划分约束

1. 在完整数据集范围内，按工件/采集组与相同 SHA-256 的关系建立传递合并的有效组。关系 A–B、B–C 意味着 A/B/C 一起处理，不能仅在当前筛选候选内分组。
2. 任意有效组不能跨 train/val/test；即使一部分成员本次被排除，也要检查范围外成员的现有分配和约束。
3. 只有已知成员均为当前有效的完全 OK，才可成为纯正常训练组。含 NG、临界、待定、未分拣、过期或无法核实成员的组，不进入 train。
4. 不同图片的 OK/NG 混合组可整体用于 val 或 test。相同 hash 被判为不同类别时则是标签冲突，必须解决或明确排除冲突组，不能用自动多数表决掩盖。
5. 同内容、同结论的重复图片默认选稳定的一个代表进入包，其他记录保留且说明去重原因；不能通过重复复制放大评估样本数。
6. 手工调整以有效组为单位。为凑比例拆组、隐式覆盖旧 split、把范围外组成员自动拉入导出，均不允许。

第一版保证的是用户已声明组与精确重复的隔离。近重复、未知采集关联、跨数据集泄漏检查列为已知边界，不宣称全部覆盖。

## 5. 异常检测协议与确认路径

### 5.1 默认完整协议

默认采用独立 train / val / test：

| 集合 | 样本 | 用途 |
|---|---|---|
| train | 纯正常训练组的完全 OK | 拟合正常分布 |
| val | 独立的正常与异常组 | 选参数、选阈值及开发期间检查 |
| test | 冻结的正常与异常组 | 最终一次独立评估 |

默认建议比例为：正常候选按 80/10/10，异常候选按 0/50/50；这些是可修改的初始建议，不是对所有项目适用的科学标准。按整组分配后展示实际图片数、组数、正常/异常数量和偏离原因。

完整协议要求 train 非空、val/test 各有正常和异常图片，且组相互隔离。最小类别覆盖只保证流程可运行，不代表样本量足以得出可靠性能结论。缺陷类型覆盖不足、采集条件覆盖不足需要单独展示。

建议生成顺序为：先复核旧分配与手工整组约束，再保证 val/test 的正常和异常覆盖，最后把剩余纯正常组分配到 train 并尽量接近目标配额。使用固定 seed 和稳定组排序；找不到方案时说明未满足的约束，让用户整组调整或补数据，不把启发式搜索失败伪称为已证明无解。

样本/组不足时明确阻断完整协议，给出“补充哪类数据/哪些组”的提示；可导出明确标为“仅训练准备”的纯正常包，但不得生成虚假的 val/test，或显示独立评估已准备好。仅训练包不作为首个完整 Anomalib 模板通过的替代证据。

旧方案中的 train+test 受限协议先后置；在没有独立 val 时不默认让 test 同时承担选阈值和最终评估。

### 5.2 三步向导

1. **检查数据**：分拣有效性、坏图、组覆盖、精确重复及标签冲突；可打开对应问题队列。
2. **预览方案**：选择保留现有 split 并检查，或生成仅用于本次包的新方案；查看组和图片实际分配，支持整组调整与排除。
3. **确认并生成**：默认仅冻结导出计划；“同时写回样本划分”是独立、默认关闭的操作，需展示影响并整批确认。

计划冻结具体样本 ID、源 hash、样本版本、分拣标准版本、组映射、split、排除原因、seed、协议/适配器版本及数据集 revision；保存为应用存储工件，jobs 参数只引用有界的计划 ID/hash。

确认和复制前复核变化。数据改变要求重新预检；任务重试沿用冻结计划且不能扩大范围。可选写回使用事务和幂等回执，不与“仅下载一个方案”混成同一动作。

选择写回时，成功响应返回绑定提交后 revision 的确认计划/回执，原预览失效；接下来的导出引用确认结果，不能仍拿提交前版本而必然过期，也不能悄悄重新读取一套划分。写回失败时原 split 不变；丢响应后按回执核对和重试。

最终测试集在包内标记为评估用途。应用在数据准备范围内防止意外重分配，并记录显式重建的新协议版本；不声称可以约束用户在外部训练脚本中是否偷看测试集。

## 6. 训练包与读取器适配

### 6.1 第一目标版本及技术约束

计划以 **Anomalib 2.7.0** 为首个读取兼容目标。当前官方源码中，Folder 默认会从 test 生成 val，且没有专用 val_dir 参数；Tabular 的默认构建也仅直接初始化 train/test。不能仅把三个目录或一列 split 写入包，就声称独立 val 已被实际使用。

因此先做一项小型可行性验证：基于公开数据集/数据模块接口，以清单分别建立 train/val/test，关闭额外随机重分配，核对 setup 后实际的三个集合。优先使用一份随包提供的轻量适配脚本；不建设训练平台，不修改用户 Anomalib 安装。

Anomalib 及其 PyTorch 依赖只进入单独的读取验证环境，首选 Python 3.12 CPU；不成为 Dataset Manager 基础安装或便携包的必要依赖。具体环境锁文件在真实运行后生成，当前未安装或验证该组合。

来源：[Anomalib 2.7.0 发布说明](https://github.com/open-edge-platform/anomalib/releases/tag/lib%2Fv2.7.0)、[固定版本 Folder](https://github.com/open-edge-platform/anomalib/blob/lib/v2.7.0/src/anomalib/data/datamodules/image/folder.py)、[固定版本 Tabular](https://github.com/open-edge-platform/anomalib/blob/lib/v2.7.0/src/anomalib/data/datamodules/image/tabular.py)、[固定版本划分实现](https://github.com/open-edge-platform/anomalib/blob/lib/v2.7.0/src/anomalib/data/datamodules/base/image.py)。以上是接口核对，不能替代真实加载验收。

### 6.2 包内容

```text
工业异常检测数据包/
  train/good/...
  val/good/...
  val/defect/...
  test/good/...
  test/defect/...
  samples.csv              # 相对路径、label_index、split、稳定样本标识
  manifest.jsonl           # 原始 hash、判定、组、映射和追溯信息
  protocol.json            # 规则、seed、版本、冻结范围
  export-report.json       # 数量、排除原因、告警、内容校验
  load_anomalib.py          # 以本文件目录解析路径，分别建立三个集合
  requirements-reader.txt # 实测后的固定读取环境
  使用说明.md
```

目录只表达二元 normal/abnormal 及 split；多缺陷、主缺陷、程度继续写清单，避免一图多份和异常多分类误解。文件名保留稳定 ID 防止同名冲突；交付目录和清单不依赖开发机绝对路径。

首版图像级包不生成 mask。NG 没有像素标注是合法状态；不以全零 mask 或整图 mask 冒充真值，也不输出像素级指标可用的承诺。已有几何标注继续保留；二值 mask 转换及像素级评估作为后续独立协议验收。

### 6.3 读取放行标准

- 从与解压目录不同的工作目录运行；移动整个包到中文/空格路径后仍可加载。
- 分别读取 train/val/test 至少一个批次，并完整遍历样本清单；实际样本标识、标签、split 与冻结计划相同。
- train 只有正常样本，val/test 正常异常覆盖正确；三个集合组及 hash 无交集。
- 数据模块在 fit/test 的 setup 阶段不能悄悄重分配或复用 test 作为 val。
- 缺文件、坏图、清单被篡改时明确失败；读取器不得在原始图片目录生成缓存或侧车。
- 不要求下载模型或执行完整训练来验证数据契约；模型训练效果由用户算法实验另行评价。

| IA5 试用定版 | 最短说明、元数据恢复演练、目录重新挂载、故障验证、重建便携包、真实用户首批/第二批试用 | 文档、维护/启动体验、packaging/windows、验收清单 | 同一最终包在干净 Win10/11 可用；恢复和中断无未解释的数据丢失；至少两位目标用户完成第二批复用 |

执行顺序为 IA0→IA1→IA2→IA3→IA4→IA5。IA0 的读取小验证提前发现接口问题；IA4 才完成正式数据包与集成验收。

### 8.1 技术边界

- 新持久化字段使用现有 Alembic，保留旧库和便携迁移流程；不另建平行的启动隐式迁移机制。
- 工业分拣资格和原几何训练资格分别实现；不把 training_split_service 的“已标注”检查全局删除。
- 新增薄路由建议为 `/api/datasets/{id}/anomaly-protocol-previews`、计划查询、显式写回确认及 anomaly-export-jobs；具体接口在对应批次定稿，本计划不代表已存在。
- 复用现有计划冻结、原子发布和任务生命周期。允许少量提取共用文件复制辅助函数，不为新模板先大改全部导出框架。
- 每个样本/分组变更必须提升 revision 并使旧预览失效。快照、导出配置和新字段保持同一语义。
- 沿用原始数据只读边界；任何复制只写新交付目录或应用托管区。

### 8.2 恢复与故障范围

保留现有数据库备份功能，增加明确的恢复演练。必须核对 SQLite、schema/版本及业务数量；若恢复历史快照还依赖 storage 中的工件，需同时备份必要文件与校验清单，不能把单个 app.db 宣称为完整工作区备份。

首先恢复到新应用数据目录，验证分拣、分组、标注及快照引用，缺失的历史下载工件明确显示不可用。原图丢失时复用重新挂载，恢复不能移动或覆盖原图。替换正式数据库仍需要用户对具体恢复结果明确确认。

必须验证：保存已提交但响应丢失、任务中断重启、导出空间不足/权限拒绝、源文件在预检后变化、旧库迁移失败、原图目录移动。不能把重复点击当作成功恢复机制。

## 9. 具体人工验收场景

1. 新建工业项目→扫描→全程不画框，只用分拣和分组生成完整训练包；原图 hash 不变。
2. 旧统一 OK 项目切入工业模式前显示影响；未复核等级不能直接进入纯正常 train，原标注和 split 不变。
3. 一个工件的多视角图片、以及通过同 hash 串联到另一工件的图片，不会跨 split；修改一张时显示整组影响。
4. 混合 OK/NG、临界、未知和过期成员的组不能进 train；相同 hash 的矛盾标签阻断并能定位。
5. 独立 NG 组不足以覆盖 val/test 时明确失败，实际数量不靠复制或拆组凑齐；仅训练模式不显示评估就绪。
6. 保存或批量提交后模拟丢响应，重新打开显示服务端真实结果；整批冲突不出现部分写入。
7. 先预览，再修改判定/组/标准/原文件，提交旧计划应拒绝；重试不扩大范围或产生不同划分。
8. 下载包换目录和工作目录，目标 Anomalib 环境实际加载 train/val/test；完整遍历与 manifest 一致。
9. 已有 v1 快照与新 v2 快照都可读，旧快照的分拣/分组明确为未记录；OK→NG、改组在新快照比较中可见。
10. 备份后恢复到新位置，核对组和判定，重新挂载原图继续操作；旧的唯一数据库和原图保持原样。
11. 两位以上目标用户分别完成自己的第一批及第二批数据；记录求助、修正、首次交付耗时及实际绕开软件的步骤。
12. 最终相同 ZIP 的干净 Win10/11 启动、导入、保存、重启、数据包导出通过，并绑定源码提交、包 hash 和已测能力清单。
13. 在约定的目标笔记本上，用约 1k/10k 图片操作筛选、分组、预检和导出，记录响应耗时、峰值内存及取消后继续工作的结果；不以百张合成图烟测代替真实容量体验。

## 10. 定版范围与后续

基础定版包含 IA0–IA5。它承诺正常样本训练数据准备、独立划分、图像级读取和可恢复使用，不承诺模型准确率。

基础版试用后按以下顺序评估后续批次，均不计入当前已实现能力：

| 批次 | 修改范围 | 验收门槛 |
|---|---|---|
| IA6 / P1 离线预测回流 | 按包 ID、样本 ID/hash 和模型运行 ID 导入分数、阈值及判定；预览匹配/冲突，建立误检/漏检候选队列 | 模型估计与人工真值分开；不同阈值/模型运行可追溯；导入不自动改写真值或旧实验结果 |
| IA7 / P2 像素级协议 | 显式确认像素标注完整性、支持范围内的几何转 mask、独立像素评估样本清单 | 无 mask/部分标注不能当空真值；不支持的孔洞/复杂区域明确阻断；真实读取与像素评估范围一致 |
| IA8 / P2 近重复复查 | 根据真实采集数据选择轻量候选发现方式，人工复核后调整组或排除 | 相似候选不自动等同于重复，也不自动删除；记录处理依据后重新生成协议 |

若根据 test 结果反复调参，应将该批视为开发回顾范围，下一次独立评估另留新的 test。有真值纠错或分组变化时保留历史并产生新版本，不能让旧指标随当前数据静默变化。

像素级 mask 协议、离线预测比较和真实需求驱动的近重复检查进入后续批次。在线模型服务、训练调度、团队权限、云同步、复杂 mask 编辑及大模型捆绑不进入本次基础定版。

本轮只形成计划并调整活动 TODO；不更新产品实现状态、不宣称上述能力已可用。CHANGELOG 和人工 ACCEPTANCE_TESTS 在对应实现与实际验证发生时再记录结果。
